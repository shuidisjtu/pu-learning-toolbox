## 3. 发现

### F1（重要，证据口径）：上游验证 P 项不是验证分区的正例子集

上游 `dataset/dataset_cifar.py:13-22` 的 `get_val_labeled` 内部执行：

```python
labels = np.array(labels)                 # 传入的是 base_dataset.targets（全量 50000 标签）
idxs = np.where(labels == i)[0]           # 从全量数据中取该正类的全部索引
np.random.shuffle(idxs)
val_labeled_idxs.extend(idxs[0:n_labeled_per_class])
```

`val_idxs` 参数只被 `np.random.shuffle`，没有参与筛选。因此：

- `val_p_loader`（`dataset_cifar.py:116-118`、`:133`）的正例来自**全量数据集**，
  而不是 `val_x_loader`（`:114`、`:134`，验证分区 5000 行）的正例子集；其中约 90%
  的样本是训练行。
- 正例选择使用的是 **clean 类标签**（`base_dataset.targets`），不是 PU 视图中的
  已标记正例。

工具箱对应实现是 `pu_toolbox/estimators/risk/vpu.py:256-262`（构造 `val_X` 与
`val_X[val_y == 1]`）以及 `:351-366`（resident）或 `:462-482`（stream）的风险计算：
验证边缘池是整份验证 PU 分区，P 项是其中的已标记正例，不读取 clean 标签，也不含
训练行。

影响与建议：

1. 两者的**函数形式**相同（`logsumexp(val_x) / n - mean(log_phi(val_p))`），但
   **P 项的样本来源、分区和标签信息不同**。D22 的“不作 PA/OA 选模”结论不受影响，
   受影响的只是“与上游逐样本一致”的证据强度。
2. 上游做法把训练行和 clean 标签带入验证诊断；工具箱做法避免这两点，更符合协议
   §2.3 对 `source diagnostic` 的边界。故**不建议**为了逐样本一致而复制上游抽样。
3. 已把 `vpu_sampling_audit.md` §8 与 `VPU.md` 第 44 行的“与上游一致，不存在
   口径分歧”改为：函数形式与上游目标一致；上游 `val_p_loader` 由全量 clean 标签
   抽样、并非 `val_x_loader` 的正例子集，工具箱使用验证 PU 分区的已标记正例，
   这是已登记的采样差异。
4. 已在 `vpu_sampling_audit.md` §10 的残留不确定性中登记该项。

用户冻结设置，需单独裁决。此项不影响 D21/D22。

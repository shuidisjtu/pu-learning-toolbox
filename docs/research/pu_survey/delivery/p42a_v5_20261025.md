# comparison v5：首个绑 v3 的比较矩阵（2026-10-25，P4.2a + D41 应用）

`pu_toolbox/experiment/survey_comparison_v5.json`（`survey-comparison-v5`）把比较矩阵从
`survey-v2.0` 切到 `survey-v3.0`，同时应用 D41 的 54 条 PA 裁定、补上 P4.2a 需要的 12 条
PU-Bench 锚点，并修正 18 条锚点的选模协议元数据。

**状态：已落地、已过覆盖率门禁，但尚未接管运行链路。** 当前 `load_comparison_protocol()` 默认
仍加载 v4（绑 v2），v3 运行尚未自动切到 v5；切换需要「按协议版本选矩阵」的解析入口，
是下一步。因此本文件现在是一份**已校验的暂存矩阵**，不是生效配置。

## 内容

| 项 | 数量 |
|---|---:|
| 单元级映射 | 288（覆盖 v3 在 v2 map 下的全部单元） |
| 行级映射 | 7（从 v4 结转，仅限 v3 仍有的行） |
| 锚点 | 64（v4 的 54 + 新增 10） |
| `magnitude_and_trend` | 25 个单元 |
| `no_direct_anchor` | 256 个单元 |
| `background_only` | 3（PN oracle 行） |
| `non_runnable` | 4（kldce 等标记行） |
| `outside_matrix` | 27 个单元（genpu/pulns/split_pu 等仍未入矩阵的 profile） |

## 三件事变

1. **D41 应用**：所有 PA 单元 `no_direct_anchor`。两篇基准都没有「本数据集 + proxy accuracy
   选模」的数字，理由与证据见 [pa_adjudication](pa_adjudication_20261025.md)。
2. **P4.2a 锚点**：`pulda` / `robust_pu` / `holistic_pu` / `lagam` 在 OA 单元的 c=0.1 格上拿到
   PU-Bench Table 1 的锚点，记 `magnitude_and_trend`。`lagam` 只有 Spambase 一个可运行格，
   另两个数据集的锚点不写——写了也没有单元可挂，覆盖率门禁会当孤立锚点拒绝。
3. **元数据修正**：18 条 PU-Bench 单元锚点的 `selection_protocol` 由 `proxy_acc` 改为
   `labeled_val_macrof1`，映射的 `protocol_differences` 同步写成
   「benchmark 用真标签验证集的 macro-F1 选 checkpoint，我们用 clean-validation accuracy」。

## profile map v2

`survey_comparison_profile_map_v2.json`（`survey-profile-map-v2`）绑 v5 与 v3 摘要，
把 `pulda`/`robust_pu`/`holistic_pu`/`lagam` 由 `not_in_matrix` 转 `mapped`
（13 mapped / 10 not_in_matrix）。这是 v5 的配套：没有它，那四个 profile 的单元在枚举时会被跳过，
v5 就会缺少 P4.2a 本来要补的条目。

## 覆盖率与唯一性

`validate_comparison_coverage(v3, v5, profile_map=map_v2)` 通过：

- 288 单元、288 单元映射、7 行级映射、64 锚点、27 outside_matrix；
- 每个锚点被且仅被一条映射引用（64/64，无重复、无孤立）；
- `self_pu_full_meta` **没有**自己的映射：按 D40 继承 `self_pu`，覆盖率用 profile map 翻译后
  与 `self_pu` 合并，因此同一个锚点不会在两处各算一次。

## 怎么生成的

`tmp/build_comparison_v5.py`（暂存脚本，未入库）：从 v3 的 `execution_units` 按单元类别
（PA / OA 有锚点 / OA 无锚点 / SAR / PN oracle / non-runnable）套规则生成，复用 v4 的锚点、
来源、矛盾与行级映射，`revisions` 追加一条说明。生成后立刻用与手写矩阵相同的覆盖率门禁校验，
不是「按规则填完就算数」。

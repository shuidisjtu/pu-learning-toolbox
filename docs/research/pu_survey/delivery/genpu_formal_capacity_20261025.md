# GEN-PU 正式预算容量（2026-10-25）

结论先行：**本机 T600 跑不动正式配方，32 GiB vGPU 上 100 GAN + 100 PN 轮约 2.7 小时**，
峰值显存 2.55 GiB，逐组件快照 43.4 MiB（64 MiB 上界内，余量 1.47×），100 份快照占 4.55 GB。

## 为什么先测容量

v3 的 `budgets.genpu` 声明了正式预算：100 份 `synthetic_pn` 快照、逐组件 64 MiB 上界、
batch 64。声明是死的，能不能按时按盘跑完是活的；10-23 的实测只有 1 GAN + 3 PN 轮，且是在
A6000 上。这次用两组短预算解方程，把「一个 GAN 轮」和「一个 PN 轮」的成本分开：

- GAN 轮每 batch 3D + 2G，PN 轮每 batch 1C，两者量级不同，混在一次运行里算不准；
- 跑 (2 GAN, 1 PN) 与 (1 GAN, 2 PN)，解 2×2 方程得到每轮成本，再外推到 100 + 100。

两次运行都在生产路径上（`build_genpu_recipe` → `GenPURecipeTrainer` → 逐 epoch 快照），
输入是真实的 `cifar10/split_0`（45,000 训练行），不是 10-23 那个 24 行工程子集。

## 实测

| 指标 | 数值 |
|---|---|
| 主机 | NVIDIA vGPU-32GB（33,794,359,296 B）、驱动 580.76.05、torch 2.13.0+cu130 |
| (2 GAN + 1 PN) | 175.17 s |
| (1 GAN + 2 PN) | 116.02 s |
| 每 GAN 轮 | **78.1 s** |
| 每 PN 轮 | **19.0 s** |
| 100 + 100 外推 | **9,706 s ≈ 2.70 h** |
| 峰值显存 | **2,741,134,848 B ≈ 2.55 GiB**（总 31.5 GiB，占 8%） |
| 逐组件快照 | **45,542,453 B ≈ 43.4 MiB**，上界 64 MiB，余量 1.47× |
| 100 份快照磁盘（单候选单次） | **4.55 GB** |

10-23 在 A6000 上测到的单份快照是 45,542,038 B，与这里的 45,542,453 B 只差 415 字节——
同一配方、同一宽度，序列化元数据的细微差异，说明这次的输入/模型与冻结配方一致。

## 本机 T600 的判定

batch 64 下 T600 占用 2.8 GiB / 4 GiB、利用率 97%，但**约 20 分钟没有跑完一个 GAN 轮**。
按这个速率，正式预算需要 20 小时以上，且 4 GiB 显存没有余量做长跑。所以正式预算不在本机跑，
探测中止并迁到 32 GiB 实例；这条结论是「本机不可行，需要 A6000/AutoDL」的直接证据，
不是猜测。

## 边界

- 这是**容量测量**，不是训练结果；探测用的两组短预算不产生可比较效果。
- 外推假设每轮成本恒定；求解出的每轮成本含少量固定开销，因此略偏保守。
- 逐组件上界只对同一配方/宽度成立；换宽度或加图像分辨率要重测。
- 正式 100 + 100 轮的实际落盘、回收与 manifest 是运行收据的事，不是这一份。

# v3 协议冻结（2026-10-24）

把 `survey_protocol_v3_draft.json` 就地转正为 `survey_protocol_v3.json`（`protocol_version: survey-v3.0`），
并冻结第一批已验证的阶段预算与执行单元。**不做增量测试扩张；判定依据是已交付的工程路径与重启后的门禁。**

## 变更

1. **身份 schema**：协议声明 `profile_identity_schema_version: survey-profile-identity-1`，
   22 个 profile 补齐 `algorithm`，`pulns`/`lagam` 标记 `supervision: independent_clean_support`。
   `survey_profile_identity.PROTOCOL_VERSION` 由 `survey-v3.0-draft` 改为 `survey-v3.0`。
2. **预算冻结**：`genpu`、`pulda`、`robust_pu`、`split_pu`、`holistic_pu` 的 `draft_*` 占位预算
   换成显式 `staged_budget` 合同（schema 1/2），参数取自各自 profile，快照数为原生阶段上界
   （GEN-PU 100、PULDA 120、Robust-PU 30、Split-PU 40、Holistic-PU 130），逐组件字节上界 64 MiB。
   同时补齐 `*_native_mlp` 的 backbone spec，使原生二维架构身份与 profile 对齐。
3. **单元翻牌**：10 个 native_2d 单元（上述五方法 × spambase/imdb）由 blocked 转 runnable，
   模型身份改为 `<method>_native` / `<method>_native_mlp`，比较组按 `<dataset>/native_2d/<method>` 重建。
   runnable 单元数 **22 → 32**（总单元 63 → 58；本批稍后恢复 GEN-PU/PULDA 图像行后为 **34 / 60**，见下）。
4. **review 收口**：`v2_p4_clean_support_policy`、`v2_p10_self_pu_scope` 由 pending 改 `accepted`，
   `review_status` 改 `accepted`。依据是 25 份 support 制品与 Self-PU full-meta 路径的交付，
   以及本仓的技术复核意见；不代填任何人签署。
5. **formal_blockers 重写**：删掉“profile 仍是 draft”“P4.1-B 预算未冻结”两条已不成立的说法，
   改为列出仍未接通的 9 个方法与 5 个方法的图像行。

## 图像行

`survey_staged_budget.validate_protocol_budgets` 原先要求阶段预算单元必须是 `native_2d` 且使用
`<method>_native` 架构身份，因此五个方法的 cifar10 `native_cnn` 行无法与阶段预算共存。

本批给验证器补了 native-CNN 分支：阶段预算现在允许 `native_cnn` 单元，架构身份为
`<method>_native_cnn`、backbone spec 为 `{"algorithm_id": ..., "architecture": "resnet18_small_image"}`。
GEN-PU 与 PULDA 的两行因此恢复并置 runnable（单元 58 → 60，runnable 32 → 34）。

装配验证（CPU、随机像素、不训练）：`prepare_image_bundle` 产出的随机冻结 ResNet-18 被
`assemble_model` 正确注入，得到 `GenPUClassifier`（100 份快照）与 `PULDAClassifier`（120 份），
与冻结的阶段预算一致。**尚未**跑通一次完整的 Survey CLI 图像训练，第一次真实运行需要留意显存与快照回收。

仍未恢复：Robust-PU/Split-PU/Holistic-PU 的 cifar10 行（它们没有原生 CNN，计划改走
`cnn_feature_adapter`），以及 GradPU（估计器接收 `model` 而非 `encoder`，需要单独装配分支）。

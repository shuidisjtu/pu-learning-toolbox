P2.2 新增 `scripts/verify_survey_result_receipt.py`。它只读原始字节：

- 按选定原索引逐批检查 manifest 数量、总字节与相对路径树摘要；齐备后才核整体摘要。
  排序按 POSIX 相对路径，整体批序使用原索引的 batches 顺序，不受 CLI 参数顺序影响。
- 原始和 10-09 索引可显式选择，报告记录该索引的字节 SHA、生产 commit 和身份块。
  不改换行，不重写旧索引，不解析/执行收到的脚本或 pickle/权重。
- 可分批提供根。缺根/少 manifest 为 incomplete（退出 2）；齐数但字节/路径/摘要不符、
  多文件或非法输入为 failed（退出 1）；身份完整才 verified（退出 0）。
  少量部分文件不能据缺少的逐文件基准判为正确，partial 不产出整体验收。
- 拒绝重复/重叠根、已知合并副本、manifest/子目录链接、不稳定上传及非法索引。
- 可用 `--reports` 对原索引列出的分析报告/白名单/命令证据逐文件核字节身份。
  未提供时明记 not_requested，不猜测已经收到。
- **所有路径的 formal_acceptance=false**：身份通过只允许进入下一步独立重放，
  不能证明指标合理、checkpoint 可加载、方法学成立或任何人已签署。

接收示例（根路径必须指向真实原批次，保持目录布局；先停止写入并完成上传）：

```bash
python scripts/verify_survey_result_receipt.py \
  --index docs/research/pu_survey/data/p2_2_artifacts_index_20261009.json \
  --batch-root B1=/received/B1 --batch-root B2=/received/B2 \
  --batch-root B3a=/received/B3a --batch-root B3b=/received/B3b \
  --batch-root B4=/received/B4 --reports /received/analysis
```

该索引登记的 manifest 仅 **90,757,836 bytes（约 86.6 MiB）**，可先交这一层，
再交计划、日志、报告及选中权重；不是要求先传所有逐 epoch 权重。
传输须保持原始相对路径和字节，不用扁平副本。输出 JSON 到 stdout，不改输入。

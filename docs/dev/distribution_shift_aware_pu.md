# 分布漂移感知 PU：设计说明

## 1. 目标与接口边界

源域训练数据和目标域部署数据可能来自不同分布。工具箱将三个任务分开：

- **漂移审计**：`analyze_pu_shift` 衡量两个域在特征上的可分性，并报告源域覆盖和边际权重的稳定性。
- **部署诊断**：监控逐窗口变化、分析类先验和标记倾向、为已拟合模型生成复核队列。
- **适配研究**：调用方自行定义训练和验证协议，或使用独立的联合漂移研究估计器。
  漂移审计不训练 PU 分类器，也不比较适配前后的效果。

## 2. 问题设定

源域和目标域分别记为 `p_s(x,y)` 与 `p_t(x,y)`。审计要求源域特征、与之对齐的 PU 标签、
以及目标域特征；目标域 PU 标签可选。`1` 表示已标记正例，`0` 表示未标记样本，并非已知负例。
域分类只使用特征和域身份，PU 标签用于计算标记比例和报告就绪状态。

| 情况 | 解释边界 |
|---|---|
| 可分性较低 | 当前审计未发现明显差异，不等于两个分布相同。 |
| 协变量漂移 | `p_s(x)` 与 `p_t(x)` 不同、`p_s(y\|x)` 与 `p_t(y\|x)` 相同且有足够覆盖时，边际密度比可用于加权。 |
| 类先验、概念或联合漂移 | 单次边际域分类不能识别漂移类型；普通边际权重不保证修正。 |
| 源域覆盖不足 | 重要性权重无法补回源域中缺失的目标样本；优先补数据。 |

域 AUC 不验证 SCAR/SAR、先验正确性或条件分布不变性。源域上的模型验证也不能替代目标域评估。

## 3. 密度比与审计实现

Kumagai 等人的 [AISTATS 2025 工作](https://proceedings.mlr.press/v258/kumagai25a.html)
使用两个域的 PU 数据和类先验，学习有界的相对**联合**密度比
`p_t(x,y) / (alpha * p_t(x,y) + (1-alpha) * p_s(x,y))`，并交替优化共享表征、分类器与权重模型。
独立审计只估计可观测的**边际**密度比，不等同于该联合方法。

审计使用带标准化的逻辑回归预测域身份。用分层留折预测计算方向不变的域 AUC
`max(AUC, 1 - AUC)`。另用全域数据拟合域分类器，对源域行预测目标域概率 `q`。
概率裁剪后，计算边际比和归一化前的相对权重：

```math
r(x)=\frac{q(D=t\mid x)}{1-q(D=t\mid x)}\frac{n_s}{n_t},
\qquad
w_\alpha(x)=\frac{r(x)}{\alpha r(x)+(1-\alpha)}.
```

`1/alpha` 是**归一化前**的上界，默认 `alpha=0.1`。导出的源域权重再归一化为均值 1，
供调用方按源域行位置对齐。报告保留裁剪率、分位数、归一化前的均值及上界触及率，以及有效样本量
`ESS = (sum(w))² / sum(w²)`。

默认域 AUC 严重度为 `< 0.60`（`low`）、`[0.60, 0.75)`（`moderate`）、`>= 0.75`（`high`）。
当 `ESS / n_source < 0.50`、上界触及率 `> 0.05` 或归一化前平均相对权重 `< 0.10` 时，报告覆盖警告。
这些阈值是工程启发式，不是统计检验或适配保证。`adaptation_ready` 只表示目标域 PU 标签可用且覆盖检查通过；
没有目标域标签时仍可生成审计和权重。

## 4. 如何使用审计权重

如需评估重加权是否有效，应由调用方先确认协变量漂移与覆盖假设，再选择真正支持
`sample_weight` 的估计器，并让权重和训练行严格对齐。归一化后的相对权重并非原始密度比，
不能视为对目标风险的精确校正。比较未加权与加权模型时在独立目标验证数据上作选择，
最终测试数据只用于报告。没有足够目标监督时，按指标前提报告可计算的证据，而不是宣称目标性能改善。

## 5. CLI 与部署诊断

- `shift-audit`：保存 `shift_report.json`、`shift_report.md`、`source_importance_weights.csv`。
- `shift-monitor` / `PUShiftMonitor`：使用固定参考域，记录窗口 AUC、ESS、标记率变化和告警。
  历史不保存原始样本，恢复后仍需提供参考数据，且配置要匹配。
- `analyze_domain_assumptions`：分别解析或估计两域类先验，以 `P(S=1)=P(Y=1)·c̄` 推导平均标记倾向。
  行级 bootstrap 在重采样时重新估计未知先验；平均倾向不识别特征依赖 SAR。
- `review` / `analyze_pu_uncertainty`：对已拟合的预测器生成拒绝预测、覆盖率及人工复核队列。
  概率边际不是统计置信区间。CLI 只应加载可信的本地 pickle 模型。

具体用法见[漂移审计指南](../user/howto/distribution_shift.md)。不一致的特征维度、非有限输入或非法参数应报错；
域分类折数按两域样本量限制，少于两折不能评估。覆盖不足则返回带警告的审计，不等同于输入非法。

## 6. 联合漂移研究与证据

- `JointShiftPUClassifier`：用软类别成员估计类条件域比，乘以类先验比后有界化，再交替更新 PU 分类器。
  这是 sklearn 研究求解器，而非论文神经方法的精确复现。
- `DynamicJointShiftPUClassifier`：Torch clean-room 实现，包含论文式 PU 目标、绝对值风险修正、
  共享表征和 Algorithm 1 的两阶段梯度隔离；全批次实现用于检验公式和更新边界。
- `JointShiftPUBaseline` 与 `build_joint_shift_estimator` 提供 `trPU`、`tePU`、fine-tune、
  五核 RBF-MMD、two-step 和损失修正消融。
- `benchmarks/joint_shift` 在 Wisconsin 表格数据上做概念漂移 smoke，记录多种子、Student-t 95% CI
  和集合重叠审计，`paper_claim=false`。公开公式的实现与工程验证不等于作者源码等价或论文数值复现。

工程验收包括固定种子的同分布和均值漂移对照、相对权重及 ESS 数学测试、覆盖警告、序列化和 CLI 文件旅程。
研究验证及仍缺少的统计证据见[补充清单](distribution_shift_aware_pu_checklist.md)。

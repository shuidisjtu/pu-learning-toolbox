# ADR-0019:注释质量门禁

- 状态:已接受(2026-10-03)
- 触发复审:行尾注释存量清理完成时,或注释规则与门禁行为发生变更时
- 相关:ADR-0001(架构治理机制)、`docs/dev/comment_governance.md`

## 背景

注释此前只靠评审惯例约束,没有机械门禁。一次盘点发现两类实际失效:

- `pu_toolbox/registry/builtin_methods.py` 的 docstring 指向已被删除的
  docs/dev/resources.md,同文件另一处指向更早已被改名的 resources_optimized.md。
  两处都未被任何门禁发现——当时的文档链接门禁扫描语料只有 Markdown,管不到源码注释;
- `scripts/check_test_quality.py` 头部指向的文档路径漏了 `dev/` 一级。

现有门禁覆盖文档链接、结构、公式渲染、格式等,唯独不含注释本身。

## 决策

1. **新增注释质量门禁脚本**,默认扫描生产包,三条规则:遗留标记为 error;
   裸 `TBD`(其后既非 `:` 亦非 `(`)为 error;非工具链行尾注释为 advisory。
2. **未完成事项统一用 `TBD`**。切换成本为零(生产代码存量 0 条),而 `TODO` 类标记
   的语义已被各工具链泛化为"任意待办",失去"必须带追踪上下文"的约束力。
3. **行尾注释只做 advisory**。接入时存量 144 条,一次性阻断会让门禁先成为迁移障碍;
   按目录清理时以 `--strict-inline` 局部提升为阻断。
4. **引用存在性检查并入既有文档链接门禁的路径规则**,不在新门禁中重写:该门禁
   已有路径解析与根白名单,重复实现正是 ADR-0001 单源助手机制要防的。扫描语料
   扩为生产包与脚本目录的 Python 文件;**排除测试目录**——那里的失效路径是门禁
   自身的负向夹具。
5. **CI 取阻断式接入**,不设 advisory 阶段:门禁的 error 面在接入时于生产代码上
   为 0 条,即"当前必然通过、违规必然失败",满足架构原则 §3.2"门禁必须能失败"。

## 备选方案

- **只靠评审惯例**。两处失效引用在两份文档被删除时都未被发现,说明人工核对会在
  文档重构时漏掉源码侧引用。否决。
- **CI 先跑 advisory 独立 job 再升级**。该 job 在 error 面为 0 的基线上永远为绿,
  属于架构原则 §3.2 判定为"无价值"的检查类型。否决。
- **引用存在性在新门禁中独立实现**。与新门禁的职责(注释卫生)不同源,且复制既有
  解析逻辑。否决。

## 后果

- 注释规则从惯例变为机械约束;注释治理文档成为该主题唯一真相源,
  贡献者可见入口在 CONTRIBUTING 的注释规则小节。
- 接入时的 144 条行尾注释成为已知技术债,由后续批次按目录清理,不在本决策内消化。
- 源码注释中的文档引用自此受门禁保护,文档重构不再会静默留下失效指针。
